# 知识与非虚构作品

按书的真实结构梳理，不预设它必须是操作手册。

## 选择分析维度

| 内容 | 梳理重点 | 避免 |
| --- | --- | --- |
| 实用/管理/技能 | 问题、概念、步骤、条件、案例、常见误区 | 把个案当普遍效果；只摘口号 |
| 科普/学术 | 定义、机制、推理链、证据、模型假设、局限 | 省掉结论前提；把作者解释当共识 |
| 思想/哲学/评论 | 核心问题、命题、论据、反驳、概念关系 | 强行写成几个行动步骤 |
| 历史/传记/回忆录 | 时代、事件、人物、因果解释、叙述立场 | 将回忆等同完整客观史实 |
| 参考/工具书 | 按使用问题组织目录、定义和相互关联 | 杜撰从开头到结尾的论证线 |

## 单元内容

每单元用一句话说明它解决的问题或推进的命题。提取足够支持理解的要点，重要模型使用表格，流程用步骤。保持概念间的关系，不将作者的例子从适用情境中抽离。

用 `origin` 区分：

- `source`：作者主张、定义、论证或案例的准确概括。
- `interpretation`：整理者指出的关系、批评、可推导含义，写成“可理解为/一种解读是”。
- `editorial`：新增练习、使用建议或比较框架，不冒充书中原方法。

为 `source` 和 `interpretation` 逐项列出实际支持的段落。遇到证据只能支持较窄结论时，缩小概括。对多个来源有冲突的主张，保留冲突。

## 适合实践时才增加

- 情境检索：用书内确实存在的方法设置 `routes`。每条推荐列出具体单元；无命中时显示未找到，不自动编造解决方案。不承诺关键词匹配等于诊断。
- 模板：仅为可应用的方法提供可填的表单，如方案评估、观察记录、实验或复盘。写明整理者补充，内容须能追溯方法来源。
- 复习题：先自答再展开参考要点；解释为何成立及在哪些条件下不成立，避免照抄标题作答案。

## 全书综合

综合框架应在逐章阅读后形成，并链接相关章节。按主张、支持证据、局限和适用情境汇总更有用，不是把每章第一句话串起来。

覆盖清单区别主要正文、前言后记、注释附录与索引。附录若承载关键方法要整理；书名页、重复目录、版权页可列为排除且说明，不当作“知识章节”。
