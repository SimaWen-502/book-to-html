# 小说与叙事作品

小说的整理目标是帮助理解作品，而不是把故事变成知识点口诀。先逐章读取并维护人物、事件和叙述视角记录，再写跨章分析。

## 核心模块

| 模块 | 需要说明 | 来源与判断边界 |
| --- | --- | --- |
| 阅读导览 | 体裁、人物入口、背景与阅读路径 | 不捏造未给出的出版或创作背景 |
| 分章/分场景情节 | 发生了什么，冲突如何推进，改变了什么 | 按真实章节定位；分卷、插叙、梦境需分清 |
| 人物 | 愿望、行动、障碍、关系、变化与关键选择 | 区分人物自己的话、叙述者评价与实际行为 |
| 人物关系 | 关系种类、变化节点、利益与冲突 | 同一人物别名统一；关系可能随章节改变 |
| 时间线 | 故事事件的先后、作品呈现的顺序 | 明确“故事时间”与“叙述顺序”；时间不明写相对顺序 |
| 主题与意象 | 反复出现的问题、物件、场景、象征读法 | 先列文本证据，再提出解读；不宣称唯一正确 |
| 叙事技法 | 视角、可靠性、铺垫、对照、反讽、节奏等 | 说明具体例子及作用；不乱用术语 |
| 阅读讨论 | 值得争论的选择、意义和替代解读 | 参考回应是有依据的读法，不是标准答案 |

短篇集按作品分别整理，再综合共同主题；不要把不同故事的人物合并成一个世界。多线叙事可以按章节与人物线双向导航，保证人物线没有改写原书叙述顺序。第一人称的“我”不自动等于作者；叙述者猜测不自动等于事实。伏笔必须有前后证据，避免因为知道结局而杜撰预示。

传记、纪实文学用“人物/事件/叙述”结构，但标记为非虚构或混合；不能因形式像小说就虚构对话、动机和历史因果。寓言与故事型实用书可同时保留故事和作者明确阐释的论点，注明两者关系。

## 剧透管理

默认完整梳理，但为 `mode=fiction` 设置 `spoiler_default=hide`。含关键转折、结局、后期人物关系、全书时间线和跨章分析的单元标为 `spoiler=true`。

- 目录标题用中性名称，例如“第八章：情节与人物”，不要把凶手、死亡、身份反转写入标题。
- 默认可见的总览、摘要、关系表与问题推荐也需检查是否泄露后续剧情。检索结果只推荐当前可见单元。
- 若某个模块同时有无剧透简介和结局分析，拆成两个单元，不让隐藏的参考答案泄露在可见问题里。
- 用户明确无剧透或指定阅读进度时，只提取获准范围进行输出；不能仅靠页面隐藏后续内容。
- 剧透开关是阅读体验控制，不是文件加密。HTML中完整内容仍然存在，不声称它能够保护秘密。

## 事实与解读

用 `source` 写剧情事实及文本中明确陈述的信息。用 `interpretation` 写心理动机推测、象征、主题或叙事效果；尽可能给出另一种成立的读法或指出歧义。用 `editorial` 写讨论题、对照框架和整理者绘制的图示。

人物卡可含“初始状态→关键选择→变化→最终状态”，但最终状态须放在剧透单元。时间线与关系图要逐项回查，不根据常识补足空白。引用译本中人物原名时保持一致，有矛盾则列别名表而非随意统一。

小说默认不生成工作问题检索、GROW或绩效表等实用书模板；可用“人物/主题检索”路由，或提供阅读记录、人物证据表和讨论笔记。书中伦理与角色行为不等于现实行动建议。
