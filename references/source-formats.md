# 输入与提取

先检查文件存在、格式、章节和提取质量。元数据不一定准确；书名、作者与版本不确定时如实说明。

- EPUB：以 OPF spine 为正文顺序，读取 NCX/nav 目录；注意一个章节可能被拆成多个XHTML，一个XHTML也可能含多个章节。剔除重复目录、版权和空页，保留其排除记录。图片路径相对所在内容文件解析。原书的外链与脚本均不执行。
- PDF：使用文本层提取并按物理页编号。正文分页、印刷页码与扫描页序号不同。抽查开头、中间、结尾及图表附近，警惕多栏、脚注和表格读序。文本过少的页列为疑似图像页，OCR后核对；不能将空文本页算已读。PDF脚本可用PyMuPDF或pdfplumber，缺失时先定位环境的现有依赖。
- DOCX：提取段落、标题和表格行。文本框、公式、图表、批注与嵌图可能需要文档技能或渲染回查，不能只看基础段落就声称已覆盖全部内容。
- TXT/Markdown：确认编码，UTF-8失败后尝试原文件可能的编码；识别章节标题与段落。没有可靠章节边界时，用段落来源定位，手工确定章组。
- HTML：只提取正文与标题，排除脚本/样式，不执行内容；图片须从实际可访问的来源单独检查并嵌入。
- MOBI/AZW及其他格式：如已有可靠转换工具可先转EPUB/TXT，保留转换记录；受保护或无法转换时说明读取限制，不假装已读，也不寻找盗版代替源书。
- 扫描图片、音频书：先用适合工具做OCR或转写，核对漏页、说话内容、人物名和专有词。工具或文件不足时继续可处理范围，明确未读部分。

辅助提取脚本是起点。`warnings`、重复目录、低文本页、异常字符与遗漏媒体需要人工核查。断字、繁简和标点清洗不能改变人物名、公式、数字或引用原意。长书分批读取source.json或输出的segments文本，检查工具输出是否被截断。

为每本书建立覆盖表，示例：

```json
{"label":"第三章","segments":["S0008","S0009"],"status":"read","reason":""}
```

`read`代表实际阅读并整理，`excluded`代表有理由排除，`unread`代表尚未可靠读取。`full`覆盖声明只在所有目标范围均已读且非内容性排除有记录时使用。计数来源于实际结构，不用提取文件数冒充章节数。
